# livingbraiding

## Краткое описание проекта

- **Название**: LivingBraiding
- **Короткое описание**: внутренняя CRM студии «Живём Плетём» для клиентов, записей и визитов, консультаций и броней, склада комплектов, продаж и работ с товарами, графика мастеров, почасовой работы, фонда ЗП и управленческой отчётности
- **Назначение**: автоматизация ежедневных процессов студии и фиксация финансовых операций «как было на момент события» (для корректной истории и отчётов)
- **Пользователи**: сотрудники студии (переключатель «Кабинет» — активная роль)
- **Роли**: Суперадмин, Старший админ, Админ, Мастер, Помощник, Техспец

## Функциональность

- **Клиенты**: карточка, контакты, статусы активности / ЧС, статистика и возвращаемость, история, привязка записей/визитов
- **Записи и визиты**: брони, консультации, проведение визитов (услуги, анкеты, материалы, фото, комплекты)
- **Склад**: комплекты (остатки, резервы; у старшего админа — расширенное управление / массовое обновление цен)
- **Продажи и работы**: продажа товаров/комплектов; работа с товарами (изделия на склад); калькулятор и прайс товаров
- **Каталог услуг**: просмотр прайса; управление прайсом и полями анкет (старший админ / суперадмин)
- **График и занятость**: график мастеров, блоки времени; планы работ; почасовая работа / помощь
- **Финансы**: расходы студии; фонды и выплаты (личный / студийный); расчётные периоды (закрытие блокирует правки)
- **Отчёты и аналитика**: операционные отчёты по периоду; статистика сотрудника
- **Справка**: FAQ по роли (`/help`) и подсказки «?» по страницам
- **Техспец**: сводки данных, ограниченный SQL (`SELECT` / точечный `UPDATE`), медиа-бэкапы
- **Аудит**: история изменений ключевых сущностей (детальный просмотр — суперадмин)

## Технические сведения

- **Тип приложения**: веб-приложение для внутреннего использования
- **Backend**: Python 3 + FastAPI (ASGI), запуск через Uvicorn
- **UI**: серверная HTML-отдача (Jinja2 шаблоны), без отдельного React/Node фронтенда
- **База данных**: SQLAlchemy 2 + Alembic; по умолчанию SQLite, для продакшена рекомендуется PostgreSQL
- **Хранение файлов**: загрузки (фото клиентов/комплектов/визитов и т.п.) хранятся на сервере, при необходимости можно вынести в S3-хранилище
- **Авторизация**: логин/пароль, хэширование паролей (passlib), сессии/куки (itsdangerous); мультироли с переключением активного кабинета
- **Объём данных**: небольшой/средний (внутренний проект); основная нагрузка — операции сотрудников и отчёты по периодам
- **Структура данных**: порядка 65 таблиц в БД
