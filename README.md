# livingbraiding

## Краткое описание проекта

- **Название**: LivingBraiding
- **Короткое описание**: внутренняя CRM студии «Живём Плетём» для ведения клиентов, записей, визитов, складского учёта комплектов/материалов, продаж, расходов, расчётов зарплат и управленческой отчётности
- **Назначение**: автоматизация ежедневных процессов студии и фиксация финансовых операций “как было на момент события” (для корректной истории и отчётов)
- **Пользователи**: сотрудники студии
- **Роли**: Суперадмин, Админ, Мастер, Техспец

## Функциональность

- **Клиенты**: карточка клиента, контакты, история, привязка записей/визитов
- **Записи и визиты**: планирование, проведение визитов, привязка услуг, материалов, фото
- **Склад**: комплекты (остатки, резервы под клиента), работа с товарами “в наличие / на заказ”
- **Продажи**: продажа товаров/комплектов со списанием и учётом остатков
- **Финансы**: расходы студии, фонды/выплаты, расчётные периоды (закрытие периода блокирует изменения)
- **Отчёты**: операционный отчёт по периоду (выручка, объёмы, материал, расходы, фонды, доли сотрудников)
- **История изменений (аудит)**: изменения в ключевых сущностях фиксируются, просмотр детальной истории доступен суперадмину

## Технические сведения

- **Тип приложения**: веб-приложение для внутреннего использования
- **Backend**: Python 3 + FastAPI (ASGI), запуск через Uvicorn
- **UI**: серверная HTML-отдача (Jinja2 шаблоны), без отдельного React/Node фронтенда
- **База данных**: SQLAlchemy 2 + Alembic; по умолчанию SQLite, для продакшена рекомендуется PostgreSQL
- **Хранение файлов**: загрузки (фото клиентов/комплектов/визитов и т.п.) хранятся на сервере, при необходимости можно вынести в S3-хранилище
- **Авторизация**: логин/пароль, хэширование паролей (passlib), сессии/куки (itsdangerous)
- **Объём данных**: небольшой/средний (внутренний проект); основная нагрузка — операции сотрудников и отчёты по периодам
- **Структура данных**: порядка 42 таблиц в БД
