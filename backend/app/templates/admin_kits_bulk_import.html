Массовая загрузка комплектов (JSON)

Доступно только суперадминистратору. Корень JSON — массив объектов; допускается только строгий JSON (без // и хвостовых запятых). Лимиты: до {{ (max_bytes // 1024)|int }} KB текста, не более {{ max_kits }} комплектов за один запрос.

Если артикул уже занят в базе или в этом же файле, к сохранённому артикулу добавляется суффикс ❗повтор, при необходимости ❗повтор2 и далее (до 80 символов).

Обязательные поля

Помимо sku для каждого объекта в массиве должны быть заданы:

  • title — название (непустая строка).
  • pieces_initial — целое число > 0 (скалярный остаток «штук комплекта» при создании).
  • stock_price_total — число > 0 (цена комплекта на складе, ₽).
  • cost_total — число > 0 (себестоимость, ₽).
  • blank_type_de и/или blank_type_se — хотя бы одно true.

discount_percent не обязателен (по умолчанию 0); не должен превышать допустимую маржу относительно цены и себестоимости.

composition и blank_stock

Ключи — это kit_key из каталога «Заказ» → «Заготовки поштучно» (должна быть активная позиция с таким ключом в meta_json). Ниже — эталонный список ключей из кода приложения; в вашей базе могут быть добавлены другие ключи или отсутствовать часть строк — ориентируйтесь на каталог.

composition задаёт состав одного комплекта (сколько каких заготовок в наборе). Допустимы два вида:

  • объект "КЛЮЧ": целое_qty — только положительные целые, повтор ключей суммируются;
  • массив объектов [{"key":"SE_BRAID_LONG","qty":2}, …].

blank_stock — только объект "КЛЮЧ": целое_остаток (≥ 0; нули отбрасываются). Ключи должны входить в пересечение «есть в composition» и «есть в каталоге с этим kit_key».

Условие: если задан непустой composition и pieces_initial > 0, обязателен непустой blank_stock (остатки по видам для keyed-склада).
